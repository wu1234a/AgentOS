# AgentOS 安全与运维规范

版本：1.0

## 1. 安全目标

AgentOS 会调用能够读取和修改代码、运行工具的
Agent，因此必须将模型输出视为不可信输入。安全边界必须由服务端、Runner、操作系统和
Git 平台共同实施，不能只依赖 Prompt。

## 2. 权限等级

| 等级 | 权限                                   | 默认策略                 |
|------|----------------------------------------|--------------------------|
| L0   | 只读分析                               | 默认允许                 |
| L1   | 修改隔离工作区                         | 受项目目录和任务范围限制 |
| L2   | 提交分支、创建 PR、运行测试            | 需要规则授权             |
| L3   | 合并、部署、生产数据操作、密钥权限变更 | 默认禁止，后续必须审批   |

Agent 的权限由服务端策略决定。Agent 不能通过修改自己的 Prompt
或请求参数提升权限。

## 3. 密钥管理

- 不把 API Key、密码、Cookie、PAT 写入 Git。
- 不把密钥写入 Skill、任务 InputJson、日志或产物。
- 本地开发使用 User Secrets 或环境变量。
- 云端使用受控 Secret Store。
- 数据库只保存 SecretReference，不保存明文。
- Runner 只获得当前任务需要的最小凭证。
- 密钥轮换必须有记录。
- 任何日志写入前必须进行敏感信息脱敏。

## 4. Runner 安全

- Runner 主动出站连接控制平面，不开放公网入站端口。
- Runner 使用独立身份和短期租约 Token。
- Runner 仅能访问注册时允许的项目和目录。
- 所有路径必须规范化并验证在白名单根目录内。
- 不允许通过 `..`、符号链接或 Junction 绕过目录边界。
- 进程启动不得拼接 shell 字符串；使用 ProcessStartInfo.ArgumentList。
- 任务超时必须能终止进程树。
- Runner 不得把生产数据库管理员凭证传给 Codex。
- 取消任务时必须校验任务归属、租约和状态。

## 5. Codex 执行安全

- 先在无敏感数据的测试仓库验证 CLI 版本和执行参数。
- 使用 Codex CLI
  自身的沙箱/审批能力；不得默认使用绕过审批或沙箱的危险参数。
- 不允许把任意用户文本直接拼接成 shell 命令。
- Codex 可执行文件路径来自 Runner 受信配置。
- 工作目录必须经过白名单验证。
- 设置超时并终止整个进程树。
- 支持取消令牌。
- 对 stdout/stderr 流式读取，避免缓冲区阻塞。
- 日志脱敏。
- 不将 Runner Secret、API Key 或其他密钥注入 Prompt。
- 任务内容和 Skill 内容视为不可信/受控输入，外部网页和 Issue
  内容不得覆盖系统安全规则。
- 如果 CLI 当前版本无法提供满足要求的安全执行模式，Adapter
  必须拒绝启动任务并给出明确错误，不能退化为无约束 shell 执行。

## 6. 工作区隔离

- 读任务可以使用只读仓库快照。
- 写任务必须在独立 Worktree 或一次性工作区中执行。
- 同一个分支不能同时被两个写任务占用。
- 清理工作区前检查未提交变更。
- 不自动删除唯一副本或未归档产物。
- 对外部 PR 使用隔离 Runner，不与个人开发环境共享凭证。

## 7. 网络安全

- API 使用 HTTPS。
- Webhook 验证签名。
- 对外请求设置域名白名单（如业务需要）。
- 防止 SSRF：不允许任意 URL 访问内网、云元数据地址或本机管理端口。
- SQL Server 不直接暴露公网。
- 管理后台启用认证和 CSRF/Origin 策略（按认证方式选择）。
- 限制请求速率、体积和超时。

## 8. 人工审批策略（后续阶段）

必须审批： - 删除生产数据或不可逆文件。 - 停止生产服务。 -
生产环境部署（初期）。 - 付款、采购下单或产生实际费用的操作。 -
新建、读取、轮换或修改密钥。 - 权限变更。 - 对外发送重要消息。 -
改变产品方向或不可逆业务规则。

审批记录必须包含： - 申请任务和 Agent。 - 操作对象。 - 风险等级。 -
Agent 建议和理由。 - 影响范围。 - 批准/拒绝/要求修改。 -
操作者和时间。 - 决策后执行结果。

审批必须由服务端验证，不能仅凭前端按钮状态判断。

## 9. 备份与恢复

- SQL Server 定期备份。
- 备份必须定期执行恢复演练。
- Skills、Rules 样例和项目配置纳入 Git。
- Artifact 文件定期备份或按保留策略归档。
- Runner 本地工作区不作为唯一数据副本。
- 任务日志和审批记录应保留足够时间用于审计。

## 10. 运维指标

至少监控： - Event 接收量、拒绝量、重复量。 - Event 到 Task
的转换失败数。 - Pending / Queued / Running / Failed 任务数。 -
任务平均等待时间和执行时长。 - Runner 在线数、最后心跳和版本。 -
租约过期次数。 - 重试次数和死信任务数。 - Agent 执行成功率。 - Token
和成本（如果 Provider 能提供可信数据）。 - API
错误率和数据库连接健康状态。

## 11. 故障恢复

- API 重启：任务状态从 SQL Server 恢复。
- Runner 断网：租约过期后由服务端重新调度。
- Codex 进程崩溃：记录失败 Attempt，按策略重试。
- 数据库暂时不可用：Runner
  不得假装任务成功；本地日志可短暂缓存，恢复后补传。
- 重复回调：使用幂等键处理。
- 达到最大重试次数：停止自动重试，进入人工处理。

## 12. 开发阶段的安全底线

AOS-001～AOS-008
不接生产环境密钥，不做生产部署，不执行生产数据操作。所有测试使用开发数据库、测试仓库和测试工作区。
